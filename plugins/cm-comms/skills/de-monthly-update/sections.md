# Canonical section skeleton

Copy this shape every month so the update is recognisable issue to issue. Drop a section
if nothing landed in it; add one only when a month's work genuinely clusters somewhere new
(say so when you do). Sections follow the **product**, not the org chart.

Bullet format — one block per point, so it stays draggable in Notion:

```markdown
- **Product outcome in plain language.** One supporting sentence, at most one clause more. — *Name*
```

Then the person's photo from `~/Desktop/de-allhands-photos` on the line beneath. Photo alone
is cleaner than photo + "— Name"; pick one and keep it consistent down the page.

---

## Product-Data

### Main App
Customer-visible fixes and accuracy work in the core app.
Sub-heading **Monetization** for catalog valuation, revenue, and pricing data.

### New Verticals — Music
Label attribution, catalog, streaming-platform coverage (JioSaavn etc.), live events,
social backfills and platform expansion.

### New Verticals — Sports
Leagues, athletes, game statistics, sports schema.

### New Verticals — Creators
Tiering, creator profiles, metadata and tags.

### Data Shares
Per-customer delivery: new shares, delivery reliability, the shares catalog.

### Data Architecture
Repo and pipeline structure, shared libraries, entity IDs, cost and warehouse load.
Usually has no screenshot — leave it text-only rather than forcing one.

### Reliability & Monitoring
Drift detection, freshness alerting, incident response, CI guardrails.

### Vendor Migration
Only while one is active. Name it: `Vendor Migration: IQData → SocialData`.

### Internal Tooling & AI
Casper, agent tooling, Flow bot, evaluation pipelines.

## Optional: What's next

Four or five lines, one per person, for work that is genuinely in flight. **Ask first** —
it has been skipped before. If it is skipped, in-flight work must be either cut or reworded
as the completed part (a design that was handed off is a real deliverable; a design is not
a shipped capability).
